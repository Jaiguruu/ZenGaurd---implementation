# Comprehensive Project Report: ZenGuard Zero-Trust Security Framework

## 1. Abstract
As cyber threats grow increasingly sophisticated, traditional threshold-based security systems frequently fail to identify anomalous behaviors, particularly lateral movement and insider threats. **ZenGuard** is a next-generation, AI-driven cybersecurity framework designed to fundamentally rearchitect enterprise threat detection and response. By seamlessly unifying Security Information and Event Management (SIEM), User and Entity Behavior Analytics (UEBA), and Security Orchestration, Automation, and Response (SOAR), ZenGuard establishes a continuous, adaptive "Zero-Trust" evaluation pipeline. 

The framework ingests high-density network telemetry, synthesizes it into key behavioral identity features, and evaluates it offline using an unsupervised Machine Learning model (Isolation Forest). The resulting non-deterministic anomalies are dynamically translated into standardized risk metrics and passed to a Reinforcement Learning (RL) powered SOAR engine. Utilizing Q-Learning algorithms trained on real-world data distributions, the SOAR orchestrates context-aware mitigation playbooks, intelligently balancing stringent security Service Level Agreements (SLAs) against operational business continuity.

## 2. Introduction & Problem Statement

### 2.1 The Limitations of Traditional Security Systems
Modern enterprises typically rely on a combination of SIEMs and static rule-based firewalls. However, these traditional architectures present critical flaws:
1.  **Alert Fatigue:** Security Operations Centers (SOC) are overwhelmed by thousands of false-positive alerts generated by rigid threshold rules (e.g., `if failed_logins > 5: trigger_alert()`).
2.  **Inability to Detect Insider Threats:** Once an attacker compromises valid credentials, static rules often fail to recognize the subtle deviations in their subsequent behavior (e.g., accessing servers at unusual times).
3.  **Manual Mitigation Bottlenecks:** Even when a threat is detected, the response (SOAR) is typically manual or governed by rigid "if-then" playbooks that lack contextual nuance, leading to delayed containment.

### 2.2 Proposed Solution: The ZenGuard Framework
ZenGuard addresses these limitations through an AI-native approach:
-   **Adaptive Profiling:** Replaces static SIEM correlation with adaptive UEBA using Machine Learning to understand the "normal" shape of a user's behavior.
-   **Intelligent Automation:** Replaces hardcoded response scripts with an RL agent that learns the optimal mitigation strategy based on risk severity and context.
-   **Explainable AI:** Solves the "black-box" problem inherent in ML models by providing a transparent "Thinking Log" that details exactly why the AI chose a specific mitigation playbook.

## 3. System Architecture & Design

ZenGuard is engineered on a strictly decoupled, microservices-based "Zero Trust" pipeline. The architecture is structurally segmented into three distinct layers communicating via REST APIs, ensuring that data ingestion, mathematical analysis, and mitigation execution remain physically and logically isolated.

### 3.1 Architectural Diagram (Conceptual Flow)
1.  **Network/Endpoints** $\rightarrow$ Raw Logs
2.  **SIEM (Logstash/Elasticsearch)** $\rightarrow$ Aggregates and buffers data
3.  **SIEM Listener** $\rightarrow$ Extracts and structures 7 identity features
4.  **UEBA (FastAPI + Scikit-Learn)** $\rightarrow$ Analyzes features via Isolation Forest, outputs Risk Score (0-100) and Context
5.  **SOAR (Python Engine)** $\rightarrow$ RL Agent evaluates state, Deterministic SLA ensures compliance
6.  **Mitigation Playbooks** $\rightarrow$ Enforce MFA, Isolate Endpoint, Revoke Privileges

### 3.2 Modular Decoupling
This decoupled nature allows for highly flexible deployment. The UEBA model can be trained entirely offline by feeding it synthetic CSVs, completely isolated from network constraints. Similarly, the SIEM can operate independently as a data lake. The integration is achieved seamlessly through API boundaries, specifically the `POST /api/soar/evaluate` endpoint.

## 4. Methodology & Subsystem Implementation

### 4.1 The SIEM Subsystem (The "Security Cameras")
The SIEM layer is responsible strictly for data ingestion, normalization, and observation.
*   **Infrastructure:** Built on the ELK stack (Elasticsearch, Logstash, Kibana) orchestrated via Docker.
*   **Data Ingestion:** Utilizing a custom `zenguard_replayer.py`, the system can ingest massive datasets (such as the CIC-IDS 2017 network captures) simulating real-world network traffic.
*   **Feature Engineering (`siem_listener.py`):** Raw network packets (Layer-4 data containing 80+ columns) are excessively noisy for behavioral ML. The listener acts as a courier, actively polling Elasticsearch and synthesizing the raw data into **7 critical identity features**:
    1.  `failed_logins`
    2.  `MFA_bypassed`
    3.  `privilege_change_attempted`
    4.  `session_duration`
    5.  `access_hour`
    6.  `external_connection`
    7.  `device_trust_score`

### 4.2 The UEBA Subsystem (The "Behavioral Profiler")
The User and Entity Behavior Analytics module bridges the gap between raw data and actionable intelligence.
*   **Algorithm Selection:** ZenGuard employs an **Isolation Forest** (Scikit-Learn). This unsupervised algorithm was chosen for its $O(n \log n)$ training speed and exceptionally low memory footprint, making it ideal for real-time, continuous behavioral scoring compared to computationally heavy Deep Learning alternatives.
*   **Training & Tuning:** The model is trained offline (`train.py`) with a contamination factor set to 5%, effectively learning the "normal" behavioral sphere and flagging outliers (representing lateral movement or impossible travel).
*   **Live Inference Server (`model_server.py`):** Exposes a FastAPI REST endpoint (`/api/soar/evaluate`). 
*   **Dynamic Risk Translation:** A core innovation in this layer is the mathematical translation of the Isolation Forest's raw decision function scores (e.g., `-0.422`) into a universal integer `risk_score` (0-100). This is achieved by dynamically interpolating across the model's learned decision boundary (`offset_`). The server also bundles specific contextual flags (e.g., `MFA_bypassed = 1`) into the JSON response for the downstream SOAR module.

### 4.3 The SOAR Subsystem (The "Autonomous Guards")
The SOAR module handles mitigation and orchestrates defensive playbooks using a hybrid AI approach.
*   **Reinforcement Learning (Q-Learning):** The `rl_agent.py` evaluates security responses as an optimization problem.
    *   **State Space:** Defined by the `risk_band` (Low, Medium, High, Critical), the `mfa_bypassed` flag, and an `anomaly_flag`.
    *   **Action Space:** 7 discrete actions ranging from "Do Nothing" (0) to "Enforce MFA + Isolate + Revoke" (6).
    *   **Reward Design:** The agent receives positive rewards for proportional responses (e.g., blocking a critical threat) and heavy penalties for under-responding to high-risk events or over-responding to benign activity (preventing "security fatigue").
*   **Vectorized Real-World Training (`train_rl_agent.py` & `collect_rl_dataset.py`):** Instead of training on arbitrary random numbers, the RL Q-table (`soar_qtable.pkl`) is trained on 400,000 real-world flow distributions extracted from the datasets, ensuring the agent memorizes optimal responses against authentic behavioral curves.
*   **Deterministic SLA Engine (`engine.py`):** Acts as the final safety net. It overrides the RL agent if corporate SLAs are at risk. For example, if the risk score hits 95, the deterministic policy hard-overrides any RL suggestion to guarantee that all three critical playbooks (MFA, Isolate, Revoke) are executed instantly. It also provides context-aware prioritization (e.g., if MFA was bypassed, enforcing MFA is moved to the top of the execution queue).

## 5. Results, Testing, and Evaluation

### 5.1 Integrated SOC Dashboard
To provide visibility, ZenGuard includes a Streamlit-based interactive Analyst Dashboard (`dashboard.py`). It allows analysts to manually configure behavioral sliders or paste raw SIEM JSON logs to simulate live mitigations. The dashboard visualizes the UEBA risk score, the severity band, and the automated responses triggered.

### 5.2 Scenario Testing Verification
The system was subjected to rigorous automated integration testing (`test_scenarios_runner.py`) to validate behavior across the threat spectrum:
*   **Scenario 1: Normal Activity:** (Low Risk) The UEBA accurately scored the behavior $<50$. The SOAR correctly learned to execute $0$ playbooks, preventing user disruption.
*   **Scenario 2: Brute Force Attempt:** (Medium Risk) Scored $50-74$. SOAR triggered the "Enforce MFA" playbook to halt the automated login attempts.
*   **Scenario 3: High Risk Anomaly:** (High Risk) Unusual access times combined with external connections scored $75-94$. SOAR dynamically escalated to trigger both "Enforce MFA" and "Isolate Endpoint".
*   **Scenario 4: The Nuclear Scenario (MFA Bypass):** (Critical Risk) Active privilege escalation post-MFA bypass scored $>95$. The Deterministic SLA Engine successfully overrode standard processing to execute all three playbooks: Enforce MFA, Isolate Endpoint, and Revoke Privileges.

### 5.3 AI Transparency: The "Thinking Log"
A major achievement of ZenGuard is its radical transparency. During execution, the SOAR engine outputs a reasoning trace. This log shows the human analyst exactly what "State" the RL agent observed, the computed Q-values for all possible actions, the agent's final choice, and any SLA-based deterministic overrides. This solves the traditional compliance issues associated with deploying AI in security operations.

## 6. Limitations and Future Scope
*   **Current Limitations:** The current UEBA utilizes an Isolation Forest which does not inherently track temporal sequencing (time-series analysis) of events across a multi-day span. The SOAR playbooks currently run in simulated execution modes rather than executing actual API calls to enterprise software like Okta or CrowdStrike.
*   **Future Scope:** Future iterations could integrate Recurrent Neural Networks (RNNs) into the UEBA for deep sequential behavioral tracking. The SOAR module can be extended with direct Webhook integrations to commercial EDR and IAM platforms to execute real-world network containment.

---

## 7. Conclusion
The ZenGuard framework successfully demonstrates a paradigm shift from reactive, rule-based security to proactive, adaptive Zero-Trust architecture. By successfully decoupling data aggregation (SIEM) from mathematical behavioral profiling (UEBA) and intelligent mitigation (SOAR), the system achieves a highly scalable, robust defense mechanism. The integration of Reinforcement Learning for optimized playbook execution, balanced by strict deterministic SLA fallbacks, ensures that ZenGuard can autonomously neutralize insider threats and compromised credentials in real-time while maintaining full analytical transparency.
